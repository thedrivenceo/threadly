## Overview

The `webhook-create-post` edge function lets external tools send posts or threads into Post Companion. Use it when you want Make, Zapier, a custom script, or another automation tool to create drafts, pending posts, or scheduled posts in your Content Bank.

**Endpoint:** `POST https://api.postcompanion.app/functions/v1/webhook-create-post`

<Callout kind="alert">
  Send the secret in the `x-webhook-secret` header. Secrets in the URL query string are not accepted.
</Callout>

## Authentication

Each Threads profile has its own webhook secret. The secret identifies the user and the profile that owns the webhook request.

<ParamField header="x-webhook-secret" param-type="string" required="true" deprecated="false">
  The profile-specific webhook secret from Settings. This must be sent as a request header.
</ParamField>

<ParamField header="Content-Type" param-type="string" required="true" deprecated="false">
  Must be `application/json`.
</ParamField>

Webhook access requires a Pro, Team, or admin account. If a plan does not include webhook access, the endpoint returns `403`.

## Find your webhook URL and secret

<Steps>
  <Step title="Open Settings" icon="settings" title-type="p">
    In Post Companion, open **Settings**.
  </Step>

  <Step title="Copy the webhook URL" icon="copy" title-type="p">
    Copy the URL shown in the Webhook section. It should use the custom API domain:

    ```text
    https://api.postcompanion.app/functions/v1/webhook-create-post
    ```
  </Step>

  <Step title="Copy the secret" icon="key" title-type="p">
    Copy the secret and add it to your automation as the `x-webhook-secret` header.
  </Step>
</Steps>

## Request body

<ParamField body="content" param-type="string | string[]" required="true" deprecated="false">
  The post text. Send a string for one post or an array of strings for a multi-post thread. Each post must be 500 characters or fewer.
</ParamField>

<ParamField body="status" param-type="string" required="false" deprecated="false">
  Optional status. Accepted values are `draft`, `pending`, and `scheduled`. If omitted, the endpoint saves a draft unless you include a scheduled date.
</ParamField>

<ParamField body="scheduled_date" param-type="string" required="false" deprecated="false">
  Schedule date in `YYYY-MM-DD` format. If you send a date without a time, Post Companion chooses a best available time and saves the post as pending review.
</ParamField>

<ParamField body="scheduled_time" param-type="string" required="false" deprecated="false">
  Schedule time in `HH:MM` 24-hour format. You must also send `scheduled_date`.
</ParamField>

<ParamField body="category" param-type="string" required="false" deprecated="false">
  Pillar category name. Post Companion matches it to a category for the profile tied to the webhook secret.
</ParamField>

<ParamField body="content_type" param-type="string" required="false" deprecated="false">
  Content type category name. Post Companion matches it to a content type for the profile tied to the webhook secret.
</ParamField>

## Example requests

<Request show-lines="true" tabs="Draft,Thread,Scheduled,JavaScript">
  ```bash
  curl -X POST https://api.postcompanion.app/functions/v1/webhook-create-post \
    -H "Content-Type: application/json" \
    -H "x-webhook-secret: your_webhook_secret" \
    -d '{
      "content": "Your post text"
    }'
  ```

  ```bash
  curl -X POST https://api.postcompanion.app/functions/v1/webhook-create-post \
    -H "Content-Type: application/json" \
    -H "x-webhook-secret: your_webhook_secret" \
    -d '{
      "content": ["Post 1", "Post 2", "Post 3"],
      "category": "Mindset",
      "content_type": "Authority Post"
    }'
  ```

  ```bash
  curl -X POST https://api.postcompanion.app/functions/v1/webhook-create-post \
    -H "Content-Type: application/json" \
    -H "x-webhook-secret: your_webhook_secret" \
    -d '{
      "content": "Post text",
      "status": "scheduled",
      "scheduled_date": "2026-06-01",
      "scheduled_time": "09:00"
    }'
  ```

  ```javascript
  const response = await fetch('https://api.postcompanion.app/functions/v1/webhook-create-post', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'x-webhook-secret': process.env.POST_COMPANION_WEBHOOK_SECRET
    },
    body: JSON.stringify({
      content: 'Your post text',
      category: 'Mindset',
      content_type: 'Authority Post'
    })
  });

  const result = await response.json();
  ```
</Request>

## Profile scoping

The webhook secret is unique to one Threads profile. Requests sent with that secret can only create content for that profile.

This means:

- Content does not leak into another connected profile's Content Bank
- Category and content type names are matched inside the same profile
- Rotating one profile's secret does not affect another profile

## Regenerate a webhook secret

Use secret rotation when a webhook secret may have been shared or exposed.

<Steps>
  <Step title="Open Settings" icon="settings" title-type="p">
    Open **Settings** and find the Webhook section.
  </Step>

  <Step title="Click regenerate" icon="refresh-cw" title-type="p">
    Click the regenerate button next to the secret and confirm the action.
  </Step>

  <Step title="Update your automations" icon="workflow" title-type="p">
    Replace the old `x-webhook-secret` header value in Make, Zapier, or your custom scripts.
  </Step>
</Steps>

<Callout kind="alert">
  Regenerating the secret immediately invalidates the old secret. Existing automations stop working until you update their header value.
</Callout>

## Error handling

| Status | Meaning |
|--------|---------|
| 200 | Content created successfully |
| 400 | Invalid payload, status, date, time, or content length |
| 401 | Missing or invalid webhook secret |
| 403 | Plan does not include webhook access |
| 405 | Method is not `POST` |
| 500 | Internal server error |
